## 1. 启动 / 停止 / 构建

```bash
cd app
npm install          # 首次
npm run build        # 构建到 dist/，同时生成离线 sw.js
npm run serve        # 局域网预览服务（默认 0.0.0.0:5199）
```

- 停止服务：在运行 `npm run serve` 的终端按 `Ctrl+C`
  （若在后台运行：`lsof -ti:5199 | xargs kill`）
- 开发模式（热更新）：`npm run dev`（同样监听 0.0.0.0:5199）
- 跑测试：`npm test`（Vitest，41 个单测）

**端口 5199** 是唯一的服务端口；只暴露 `app/dist` 目录，不把整个 Workspace 当站点根目录
（`scripts/serve.mjs` 内有路径穿越防护，并拒绝 `..` 越界）。

## 2. 手机测试入口

同一 Wi-Fi 下用手机浏览器打开：

```
http://192.168.43.22:5199/
```

二维码：`app/public/qr-lan.png`（也可重新生成：`node app/scripts/lan-info.mjs 5199`）

> 该地址来自本机 `en0` 网卡。若你的电脑 IP 变了（换 Wi-Fi、重连热点），
> 重新执行上面的 `lan-info.mjs` 命令即可。

电脑需要**保持 `npm run serve` 运行**。手机打不开时依次检查：

1. 手机和电脑是否在**同一个 Wi-Fi**（不能一个连热点一个连路由器）。
2. 电脑防火墙是否拦截了 5199（macOS「系统设置 → 网络 → 防火墙」）。
3. 路由器是否开启了「AP 隔离 / 客户端隔离」（公共 Wi-Fi 常见，会导致设备互不可见）。
4. 是否用了 VPN / 代理软件改了路由（先临时关闭再试）。
5. 用电脑浏览器访问 `http://192.168.43.22:5199/__health` 是否返回 JSON。
6. 端口被占用时换端口：`node scripts/serve.mjs --port 5200`。

**关于 PWA / 离线：**

- 局域网 `http://192.168.x.x` 属于**非安全上下文**，浏览器不会注册 Service Worker，
  所以手机上能用全部功能、但没有离线缓存，也不能「添加到主屏幕后离线启动」。
- 离线能力已在 `http://localhost:5199`（安全上下文）验证通过：SW 注册、20+ 资源预缓存、
  断网后仍可打开并继续记录（见 `verify/offline-report`）。
- 想在手机上真正验证离线启动，最简单的一步是：给这个服务加一层本地 HTTPS
  （自签证书 + 手机安装信任），或部署到一个 HTTPS 静态托管。后者属于对外发布，
  本轮未做，也不在授权范围内。

**数据空间提醒：** 协议 + 域名 + 端口共同决定浏览器本地存储空间。
从 `localhost:5199` 换到 `192.168.43.22:5199`、或换端口，都会是**另一份空数据**。
迁移测试数据请用「设置 → 导出 JSON 备份」再在目标地址导入，这不是自动同步。

## 3. 数据存储与备份

**选择 IndexedDB**（自写轻量封装，`src/db/idb.ts`），理由：

- 训练记录是持续增长的结构化数据，需要按 id/日期/状态检索；
  塞进一个不断变大的 localStorage 字符串会带来整串序列化和体积上限问题。
- 每次修改在一个 `readwrite` 事务里完成，浏览器保证原子性：中断不会写出半条记录。
- 单条记录一个 key，写入量与实际改动成正比。
- localStorage 只用于非关键偏好；主题偏好存 IndexedDB 的 `settings` 表。

**数据模型**（`src/domain/types.ts`）：

| 表 | 内容 |
|---|---|
| `plans` | 计划：若干训练日 → 热身 + 正式动作；`cursor` 是八日循环游标 |
| `sessions` | 训练实例：`active` / `completed` / `discarded` |
| `settings` | 主题、最近导出时间 |
| `meta` | 种子标记、编辑锁、恢复前快照 |

关键设计：

- **开始训练时对计划日做快照**（`createSession`）。之后改计划、改动作名、删计划，
  历史记录都不变。`verify/scenarios.mjs` 里「改名后历史不变」是实测项。
- **目标值与实际值是两个类型**：`ExerciseTarget`（计划）vs `SessionSet`（实际）。
  没有「把目标当完成」的路径。
- **`null` ≠ `0`**：`reps: null` 是未填写，`reps: 0` 是实际做了 0 次，两种状态在统计里不同。
- **递减组按大组计数**：一轮三阶段全做完算 1 个正式大组；只做部分阶段算「部分完成大组」，
  单独统计，不伪装成完整组。

**备份格式**（`src/db/repo.ts`）：

```json
{
  "format": "motion-training-backup",
  "version": 1,
  "exportedAt": 1792505272144,
  "appVersion": "1.0.0",
  "counts": { "plans": 1, "sessions": 12, "activeSessions": 0 },
  "data": { "plans": [...], "sessions": [...], "settings": [...] }
}
```

- 导入前**强制预览**：导出时间、计划/记录数、未结束训练数、文件大小、来源版本。
- 恢复是**完整覆盖**，不做合并（UI 明确写明覆盖范围）。
- 恢复前自动把当前数据存成「恢复前快照」，可随时导出或回退。
- 错误/不兼容文件在校验阶段就被拒绝，不会触碰现有数据；恢复事务失败会整体回滚。
- 数据升级在读取时补默认值（`migratePlans` / `migrateSessions`），不打断进行中的训练。

## 4. 统计口径

- 热身**不计入**正式组。
- 计划内没做的组**不算**已完成组。
- 递减组按**大组**计数（三轮 = 3 组，不是 9 组）。
- 部分完成的大组**单独标注**，不伪装成完整完成。
- 删除或纠正记录后**全量重算**，不做增量累加。
- 不同动作、不同重量含义（自重 / 外加负重 / 辅助 / 哑铃单只）**不合并**成力量分数。
- 样本不足时不画趋势（只有 1 周数据就只显示次数，不做周对比）。

## 5. 已实现的功能

**计划管理**：内置 V3.2 预设（八日循环 / 六个训练日 / 热身 / 侧平举三轮结构，逐条对齐 PDF）；
新建、复制、重命名、删除计划；改训练日名称、顺序、休息日；增删改动作、调整顺序、
搜索或自建动作名、改组数/次数区间/建议重量/休息秒数。

**首页与循环**：切换当前计划；胸/背/腿贴纸选择 + A/B 训练日；动作概览与开始训练；
继续未结束训练；推进 / 跳过循环位置；日期取设备真实时间，**不因隔天自动推进循环**；
训练日与日历完全解耦。

**训练执行**：热身勾选（不计组）；每个动作显示目标、上次真实表现、逐组记录；
加组/删组/撤销完成/跳过动作；临时替换、添加、上移下移（只影响本次）；
次数用数字键盘 + 步进，重量支持小数；备注；组间休息计时（基于时间戳，切后台回来仍准确，
可暂停/±15 秒/跳过）；结束摘要；部分完成可结束；放弃训练需二次确认。

**历史与统计**：按日期分组浏览 + 搜索 + 按月筛选；详情看每组实际数据与完成情况；
纠正备注；删除前确认；从动作查看跨次表现；训练次数/每周频率/时长/正式组数/单动作历史。

**存储与离线**：每次修改自动落库（保存失败有明确红色提示，不假装已保存）；
刷新/关闭重开都能恢复；防重复结束（结束后状态流转，重复点击被 `status` 拦住）；
同一浏览器多标签页用「单活动编辑锁」避免静默覆盖；应用更新不清空数据（升级是读时补齐）。

验证过程中发现并修掉的真实缺陷（不是 UI 文案问题）：

1. **连续点击丢数据**：每次修改都基于同一份旧 session 计算，后一次覆盖前一次 → 改为累积式 `applyChange`。
2. **底部固定条遮挡输入框**：滚动时输入框被压住，点击穿透到「结束」→ 移除覆盖式固定条，改为文档流内按钮。
3. **多位数输入被替换**：受控输入重渲染重置选区（20 → 0）→ 输入期间用本地草稿字符串。
4. **恢复后设置不刷新**：`settings` 未重新加载 → 增加 `refreshSettings`。
5. **恢复抹掉本机导出时间**：备份里的旧 settings 覆盖当前 → 合并时保留本机状态字段。
6. **单周数据渲染成巨大色块**：周对比图无下限 → 单周改为文字摘要。
7. **`null` 重量显示成 `×0kg`**：格式化缺判断 → 加 `>0` 与小数格式化。
8. **刷新后被自己留下的锁判成"另一个标签页"**：editorId 存在 sessionStorage，刷新后用 `reclaimOwnLock` 认领。
9. **多标签页只提示不拦截**：锁未持有时 `persist` 直接拒绝写入，并禁用结束按钮。
10. **重量输入框太窄导致 `62.5` 被裁成 `62`**：组记录行改为次数/重量各占整行宽。
11. **数字上半截被裁**：SpaceGrotesk ascent 偏大，输入框改用无衬线字体 + `line-height: normal`。

## 7. 未验证 / 已知限制

- **手机真机手感未验证**：所有验证都在无头 Chrome（390×844，mobile 模式）完成，
  真实 iOS/Android 上的键盘行为、滚动惯性、安全区细节需要你实测。
- **手机离线启动未验证**：局域网 HTTP 非安全上下文，SW 不会注册（见上文）。功能可用，离线不可用。
- **锁屏/后台提醒未实现**：浏览器不保证后台计时器与通知，组间休息只在页面内计时
  （基于时间戳，回到页面时剩余时间正确）。
- **软键盘遮挡**：用 `visualViewport` 估算键盘高度并顶起底部元素；极端小屏 + 大字体下可能仍需微调。
- **多标签页**：用「单活动编辑锁」阻止静默互相覆盖，后进入的标签页会看到只读提示，
  但没有做自动接管或合并。
- **备份不含历史快照链**：只保留最近一次「恢复前快照」。
- 未做账号、后端、跨设备同步、社交、AI 教练、饮食、付费功能（按范围要求）。
